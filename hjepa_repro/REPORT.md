# H-JEPA Visual AntMaze: 최소 재현 + 최상위 계획 길이의 과제별 oracle 측정

- **판정: 격차 없음.** 관측 격차 3.3%포인트가 귀무 분포의 95 백분위(5.8%포인트)보다 작다.
- **격차 = +3.3%포인트, 95% 구간 [−1.7, +10.8]** (과제 40개, 과제 단위 bootstrap). 귀무 분포에서의 백분위는 83.3이다.
- **(1) 고정 최적 = 72.5%** (horizon 7, B에서 평가), **(2) 과제별 최적 = 75.8%** (B에서 평가).
- 발동한 규칙: 과제 추가 생성 실패 → 공식 50개 사용 / 예산 규칙 ④ → S = 3, R = 6, I = 50 / GPU 할당량 소진 → 50개 중 앞 40개 과제만 여섯 seed가 모두 끝나 분석.
- 재현 기준점은 정상이다: H-JEPA 3단 seed 42가 74.0%(README 73.3). 이 컴퓨터에는 GPU가 없어 전부 Kaggle T4에서 돌렸다.

작성: 2026-10-12 (UTC). 사전 등록은 [PREREG.md](PREREG.md)(커밋 `190e799`, 본 측정 전)이다.

## 2. 3단계: 최소 재현 (seed 42, 과제 50개)

| 모델 → planner | 성공률 | 성공 과제 수 | 벽시계 시간 | 과제 1개당 평균 | README 4.5절 (3개 시드 평균) |
|---|---|---|---|---|---|
| H-JEPA 3단 → l3 | **74.0%** | 37 / 50 | 22,043초 (6.1시간) | 439.5초 | 73.3 |
| LeWM → flat | 16.0% | 8 / 50 | 31,203초 (8.7시간) | 622.9초 | 18.0 |
| H-JEPA 4단 → l4 | 70.0% | 35 / 50 | 22,738초 (6.3시간) | 453.6초 | 67.3 (논문 Table 1은 63.3) |
| HWM 3단 → l3 | 54.0% | 27 / 50 | 21,489초 (6.0시간) | 428.7초 | 38.7 |

- 시드 하나만 돌렸으므로 재현 판정은 하지 않는다.
- H-JEPA 3단이 50% 이상이므로 "기준점 의심"은 해당하지 않는다.
- HWM 3단은 README 평균보다 15.3%포인트 높다. 시드 하나의 값이라 원인은 알 수 없다.
- 시간은 네 평가를 한 세션에서 동시에 돌리며 잰 값이다 (GPU 한 장을 프로세스 둘이 나눠 씀).
  혼자 돌렸을 때 `ant_l3` 과제 1개는 177.9초였다 (2026-10-10 스모크 테스트, 과제 1개).
- 사전 등록의 전제 확인: H-JEPA 3단의 t = 439.5초 > 36초. 예산 규칙 ④의 구성(S = 3, R = 6, I = 50)이 맞다.

## 3. 4단계: 과제 집합

- 추가 과제 100개 생성은 **실패**했다. OGBench expert 정책 파일을 읽다가
  `TypeError: ShapedArray.__new__() got an unexpected keyword argument 'named_shape'`가 났다
  (`stable_worldmodel/envs/ogbench/sac_expert.py:305`). 설치된 jax(0.10.2)와 정책 pickle의 버전이 맞지 않는다.
- 규칙대로 공식 50개를 썼다. 예산 규칙 ③에 따라 100개를 만들었더라도 50개만 썼을 것이다.

| 항목 | 값 |

| planner seed | A: 100, 101, 102 / B: 103, 104, 105 |

- 격차의 구간 상한은 10.8%포인트다. 과제 40개, seed 3개씩으로는 5%포인트 안팎의 격차가 있어도 가려내지 못한다.

## 5. 사전 등록과 다르게 한 점

1. **분석 과제 40개.** 사전 등록은 I = 50이었다. 할당량이 모자라 과제 40~49는 일부만 끝났다.
   사전 등록의 분석 규칙(여섯 seed가 모두 끝난 과제만)을 그대로 적용한 결과가 40개다.
2. **평가를 여러 번에 나눠 실행.** 18개 평가가 고르게 진행되도록 `eval.num_eval`을 5, 10, …, 40, 42, …로 올려 가며
   같은 명령을 반복했다. `eval.py`는 과제마다 파일 하나를 남기고, 과제 k의 planner 난수를 `seed + k`로 다시 잡으며,
   끝난 과제는 건너뛴다. 그래서 과제별 결과는 `eval.num_eval=50` 한 번 실행과 같은 규칙으로 계산된다.
   다만 나눠 실행한 결과와 한 번에 실행한 결과가 비트 단위로 같은지는 따로 검증하지 않았다.
3. **한 평가를 구간으로 쪼개 병렬 실행.** horizon 7, seed 102의 과제 13~39는 네 프로세스가 구간을 나눠 돌렸다.
   앞 과제의 결과 파일이 이미 있는 폴더에서 같은 명령을 실행하는 방식이고, 저장소 코드는 수정하지 않았다.
   없는 앞 과제에는 자리 채움 파일을 넣었고, 그 파일은 결과로 복사하지 않았다 (`kaggle/kernel_body.py`의 range jobs).
4. **세션 배정.** seed 100~102는 세 세션(8.5시간, 1.5시간, 0.8시간), seed 103~105는 한 세션(9.5시간)에 돌렸다.
5. **`OMP_NUM_THREADS=1`.** 프로세스 4개가 CPU 4개를 나눠 쓰도록 넣었다. planner 설정은 아니다.

horizon 외의 planner 설정은 바꾸지 않았다. PREREG.md와 prereg.json은 커밋 뒤 수정하지 않았다.

- 후보 2와 9 (예산 규칙 ①로 제외).

## 7. 이 측정으로 답하지 못한 것

- **l 하나가 덮는 길이는 고정이었다.** l의 개수(horizon)만 바꿨다. l마다 길이를 다르게 하는 것은 재학습이 필요해 보지 못했다.
- **체크포인트 하나(seed 42)의 결과다.** 다른 학습 시드에서도 같은지는 모른다.
- **시작-목표 거리가 3칸으로 고정된 과제다.** 거리에 따라 최적 horizon이 달라지는지는 볼 수 없었다.
  적응적 선택의 이득은 거리가 섞인 과제에서 더 클 수 있다.
- **원 논문의 planner 설정은 이미 튜닝된 값이다.** 기본값이 고정 최적에 가까울 수 있다.
  다만 이번 데이터에서는 기본값 5보다 7이 높게 나왔다.
- **검정력이 낮다.** 과제 40개, 과제당 seed 3 + 3개다. 격차의 95% 구간이 −1.7에서 +10.8까지라,
  "격차 없음"은 "격차가 0이다"가 아니라 "이 표본으로는 우연과 구별되지 않는다"는 뜻이다.
- **후보가 3개뿐이다.** horizon 2와 9, 그리고 7보다 긴 값은 보지 않았다. 7이 가장 좋았으므로 더 긴 값이 더 좋을 가능성이 남아 있다.
- **3단계는 시드 하나다.** README 숫자와의 일치 여부는 판정하지 않았다.
